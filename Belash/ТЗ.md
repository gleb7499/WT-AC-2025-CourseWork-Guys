## 2. Требования к проекту

### Обязательный минимум (MVP) — 50 баллов

**Full-stack приложение:**

- Клиент: SPA (Single Page Application) с клиентским роутингом
- Сервер: REST API с полной CRUD-функциональностью
- База данных: реляционная БД с нормализованной схемой

**Аутентификация и авторизация:**

- Регистрация новых пользователей с валидацией данных
- Вход по email/логину и паролю
- JWT-токены (access token, refresh token)
- Минимум две роли: `user` и `admin`
- Защита маршрутов на клиенте и сервере по ролям

**Валидация и обработка ошибок:**

- Валидация форм на клиенте (до отправки)
- Валидация данных на сервере (Zod/Joi/class-validator)
- Человекочитаемые сообщения об ошибках
- HTTP-статусы соответствуют типу ошибки (400, 401, 403, 404, 500)

**Нефункциональные требования:**

- Базовая доступность (a11y): семантический HTML, alt-атрибуты, aria-labels
- CORS — настроенный для работы клиента с сервером
- Helmet — защита HTTP-заголовков
- Логирование запросов и ошибок на сервере
- Пагинация и/или фильтрация для списков (где применимо)

**Контейнеризация:**

- Dockerfile для сервера
- Docker Compose для локальной разработки (сервер + БД)
- Файл `.env.example` с описанием переменных окружения

## 3. Рекомендуемый технологический стек

### Рекомендуемый стек

**Frontend:**

- TypeScript + React (Vite)
- React Router для маршрутизации
- Zustand/Redux Toolkit для состояния (или React Context)
- Axios/fetch для HTTP-запросов
- CSS Modules / Tailwind CSS для стилей

**Backend:**

- Node.js + Express (или Fastify)
- TypeScript
- Prisma ORM для работы с БД
- Zod для валидации данных
- bcrypt для хеширования паролей
- jsonwebtoken для JWT
- cors + helmet для безопасности
- winston/pino для логирования

**База данных:**

- PostgreSQL (рекомендуется)

**Инструменты:**

- ESLint + Prettier для линтинга и форматирования
- pnpm как пакетный менеджер
- Docker + Docker Compose
