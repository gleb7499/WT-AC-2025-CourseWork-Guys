# Заключение

В результате выполнения курсового проекта разработана информационная система управления бронированием аудиторий «Не занято?», предназначенная для автоматизации процесса распределения аудиторного фонда учебного заведения между пользователями различных категорий.

В ходе работы проведён анализ требований к системе, сформулированы функциональные и нефункциональные требования минимально жизнеспособного продукта. Определены основные пользовательские роли — студент, преподаватель и администратор — с соответствующими наборами прав доступа к функциональности системы. Установлены ограничения длительности бронирования в зависимости от роли пользователя для обеспечения справедливого распределения ресурсов.

Спроектирована модель данных, включающая пять взаимосвязанных сущностей: пользователи, аудитории, бронирования, токены обновления и журнал аудита. Определены атрибуты сущностей, типы данных, ограничения целостности и связи между таблицами. Применение реляционной модели данных обеспечивает согласованность информации и эффективное выполнение запросов благодаря использованию индексов.

Разработаны алгоритмы выполнения основных операций системы. Алгоритм проверки конфликтов бронирований обеспечивает предотвращение одновременного бронирования одной аудитории несколькими пользователями путём анализа пересечения временных интервалов. Алгоритмы создания, переноса и отмены бронирований включают валидацию входных данных, проверку прав доступа, применение бизнес-правил и фиксацию действий в журнале аудита.

Спроектирована трёхзвенная архитектура клиент-сервер с выделением уровней представления, бизнес-логики и хранения данных. Разделение ответственности между компонентами упрощает сопровождение системы и обеспечивает возможность независимого масштабирования уровней.

Для реализации системы выбран современный технологический стек. Клиентская часть построена с использованием библиотеки React и инструмента сборки Vite, что обеспечивает создание отзывчивого пользовательского интерфейса с высокой производительностью. Серверная часть реализована на платформе Node.js с применением фреймворка Express и объектно-реляционного отображения Prisma для взаимодействия с базой данных PostgreSQL. Применение TypeScript для разработки обеих частей приложения обеспечивает статическую типизацию и снижает количество ошибок на этапе разработки.

Реализован механизм аутентификации и авторизации на основе токенов JWT. Токены доступа обеспечивают безопасную передачу информации о пользователе без необходимости хранения состояния сеанса на сервере. Токены обновления позволяют поддерживать сеанс пользователя длительное время без повторного ввода учётных данных. Применение защищённых cookie с атрибутами HttpOnly и Secure предотвращает доступ к токенам обновления из клиентского JavaScript и защищает от атак межсайтовой подделки запросов.

Обеспечена безопасность системы путём применения рекомендуемых практик. Пароли пользователей хешируются с использованием алгоритма bcrypt с достаточным фактором стоимости для противодействия атакам перебора. Входные данные валидируются на серверной стороне с применением библиотеки Zod для предотвращения инъекций и обработки некорректных данных. Применение библиотеки Helmet защищает приложение от распространённых веб-уязвимостей путём установки соответствующих HTTP-заголовков. Политика CORS настроена с явным указанием разрешённых источников запросов.

Разработан программный интерфейс приложения в соответствии с принципами архитектуры REST. Определены конечные точки для работы с ресурсами аутентификации, пользователей, аудиторий, бронирований, расписания и статистики. Спецификация интерфейса включает описание методов HTTP, путей, параметров запросов, форматов ответов и кодов ошибок.

Подготовлена инструкция по развёртыванию и запуску системы в локальном окружении разработки. Описаны требования к программному обеспечению, процесс установки зависимостей, настройка переменных окружения, выполнение миграций базы данных и запуск приложений. Система успешно развёрнута и протестирована в локальном окружении.

Реализованная система удовлетворяет требованиям минимально жизнеспособного продукта. Пользователи могут регистрироваться и входить в систему, просматривать список аудиторий и расписание их занятости, создавать бронирования с автоматической проверкой конфликтов, отменять и переносить собственные бронирования. Администраторы имеют возможность управления аудиториями и пользователями, отмены и переноса любых бронирований, просмотра статистики использования ресурсов. Все критические операции фиксируются в журнале аудита для обеспечения возможности анализа действий пользователей.

Возможными направлениями дальнейшего развития системы являются реализация функциональности уведомлений пользователей о создании, изменении или приближении времени бронирования, экспорт расписания в формат iCalendar для интеграции с внешними календарными приложениями, поддержка рекуррентных бронирований для периодически повторяющихся событий, реализация системы бронирования на основе запросов с модерацией администратором, интеграция с внешними системами управления расписанием учебного процесса, разработка мобильных приложений для операционных систем iOS и Android, внедрение системы аналитики для выявления закономерностей использования аудиторий и оптимизации распределения ресурсов.

Таким образом, поставленные задачи курсового проектирования выполнены в полном объёме. Разработанная система может быть использована в качестве основы для создания промышленного решения по автоматизации управления бронированием аудиторий в учебных заведениях.
