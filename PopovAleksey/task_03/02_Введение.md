# Введение

В условиях современного образовательного процесса эффективное использование аудиторного фонда учебных заведений становится важной задачей. Система бронирования аудиторий позволяет оптимизировать распределение помещений между различными пользователями, предотвращать конфликты при одновременной попытке занять одну и ту же аудиторию, обеспечивать прозрачность планирования учебного процесса [1].

Традиционные методы управления расписанием, основанные на бумажных журналах или общих электронных таблицах, характеризуются высокой вероятностью возникновения ошибок, сложностью координации между подразделениями, отсутствием оперативного доступа к актуальной информации о занятости помещений. Автоматизация процесса бронирования позволяет снизить нагрузку на административный персонал, повысить доступность информации о свободных аудиториях, минимизировать конфликтные ситуации при распределении ресурсов.

Настоящая работа выполнена в рамках курсового проектирования по дисциплине «Веб-технологии» и посвящена разработке информационной системы управления бронированием аудиторий. Тема курсового проекта — информационная система «Не занято?», предназначенная для управления бронями и расписанием аудиторий учебного заведения. Система разрабатывается для трёх категорий пользователей: студентов, преподавателей и администраторов. Каждая категория обладает определённым набором прав доступа к функциональности системы. Минимально жизнеспособный продукт включает управление аудиториями, бронирование временных слотов, ролевую модель доступа, предотвращение конфликтов при одновременном бронировании одной аудитории.

Актуальность разработки обусловлена необходимостью внедрения современных информационных технологий в процесс управления ресурсами образовательных учреждений. Применение веб-приложения для бронирования аудиторий обеспечивает доступность системы из любого места при наличии подключения к сети, позволяет реализовать централизованное хранение данных, упрощает процедуру обновления информации о доступности помещений.

Целью данной работы является проектирование и реализация информационной системы управления бронированием аудиторий с поддержкой ролевой модели доступа, автоматической проверкой конфликтов и обеспечением требований безопасности.

Для достижения поставленной цели необходимо решить следующие задачи:

- провести анализ требований к системе, сформулировать функциональные и нефункциональные требования;
- спроектировать модель данных, описать сущности предметной области и связи между ними;
- разработать алгоритмы обработки основных операций, включая создание бронирования с проверкой конфликтов, перенос и отмену бронирований;
- спроектировать архитектуру клиент-серверного приложения, определить состав программных модулей;
- реализовать серверную часть приложения на основе платформы Node.js с использованием фреймворка Express;
- реализовать клиентскую часть в виде одностраничного приложения с применением библиотеки React;
- обеспечить безопасность системы путём внедрения механизмов аутентификации и авторизации, валидации входных данных, защиты от распространённых уязвимостей;
- подготовить инструкции по развёртыванию и запуску системы в локальном окружении.

Работа выполнена в соответствии с вариантом 02 курсового проектирования. Студент Попов Алексей Сергеевич, группа АС-64, номер зачётной книжки 51. Номер варианта 02 — «Бронь аудиторий «Не занято?»». Описание варианта: система предназначена для бронирования аудиторий до того, как их займут другие пользователи. Исходные данные к проекту включают управление аудиториями, расписание, бронирование слотов, роли студента, преподавателя и администратора, предотвращение конфликтов. Программный интерфейс приложения включает ресурсы для работы с аудиториями, бронированиями, расписанием и пользователями. Основные сущности данных: Room, Booking, User, Role. Условия и ограничения для приёмки минимально жизнеспособного продукта: реализация календаря расписания, механизма предотвращения конфликтов, возможности отмены и переноса бронирований.
