# Вариант 11 — Баг-трекер «Не баг, а фича?» — Роли и действия

Краткое описание

MVP: Bug, Project, User, Attachment, Comment. UI отображает доску с багами и фильтры по статусам/приоритетам; API: /projects, /bugs, /attachments, /users. Приёмка (MVP): корректная работа фильтров и доски.

Роли и основные действия

- Администратор
  - CRUD для пользователей
  - CRUD для проектов (Project)
  - Управление правами и ролями
  - Просмотр всех багов и статистики

- Менеджер
  - Просмотр проектов, назначенных на него
  - CRUD для багов в своих проектах
  - Назначение багов на разработчиков
  - Изменение приоритетов и статусов
  - Просмотр отчётов по проекту

- Разработчик
  - Просмотр багов, назначенных на него
  - Создание багов
  - Редактирование багов (ограниченно)
  - Добавление комментариев и вложений
  - Изменение статуса своих багов

- Пользователь (Reporter)
  - Просмотр публичных проектов
  - Создание багов
  - Добавление комментариев к своим багам
  - Просмотр статуса своих багов

Примеры сценариев

- Администратор создаёт Project и добавляет участников → Пользователь создаёт Bug → Менеджер назначает Bug на Разработчика → Разработчик изменяет статус на "В работе" → после исправления меняет статус на "Готово".
- Пользователь просматривает доску багов с фильтром по приоритету "Высокий", видит критические баги и их статусы.
