# Вариант 11 — Баг-трекер «Не баг, а фича?» — Маршруты (user flows)

1. Идентификация (вход в систему)

   - Пользователь: логин → дашборд с проектами и багами
   - Администратор: логин → админ-панель

2. Подготовка данных (Администратор)

   - Заполнить список пользователей
   - Создать проекты (Project)
   - Настроить роли и права доступа

3. Работа с проектами (Администратор, Менеджер)

   - Добавить/редактировать/удалить Project
   - Настроить участников проекта
   - Управлять настройками проекта

4. Работа с багами (Пользователь, Разработчик)

   - Создать новый баг (Bug)
   - Просмотр списка багов с фильтрами
   - Редактировать описание и поля бага
   - Добавить вложения (Attachment)
   - Добавить комментарии (Comment)

5. Просмотр и фильтрация (Пользователь)

   - Просмотр списка проектов
   - Просмотр багов по проекту с фильтрами (статус, приоритет, назначенный)
   - Доска (Kanban) с багами по статусам
   - Просмотр деталей бага (описание, комментарии, вложения)

6. Управление багами (Разработчик, Менеджер)

   - Назначить баг на разработчика
   - Изменить приоритет и статус
   - Переместить баг между статусами на доске
   - Закрыть баг с комментарием

7. Отчёт / История

   - Просмотр истории изменений бага
   - Просмотр активности по проекту
