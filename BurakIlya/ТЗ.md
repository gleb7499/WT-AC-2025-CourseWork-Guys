## 2. Требования к проекту

### Обязательный минимум (MVP) — 50 баллов

#### Full-stack приложение

- **Клиент:** SPA (Single Page Application) на React с клиентским роутингом
- **Сервер:** REST API с полной CRUD-функциональностью для всех сущностей из документации
- **База данных:** PostgreSQL с нормализованной схемой по ERD из `R1_ERD.md`

#### Аутентификация и авторизация

- Регистрация новых пользователей с валидацией (username: 3-30 символов, password: минимум 8)
- Вход по username и паролю
- **JWT-токены:**
  - Access token (срок жизни: 15 минут)
  - Refresh token (срок жизни: 7 дней)
  - Refresh endpoint для обновления access token
- **Минимум две роли:** `user` и `admin` (+ другие из R1_Roles_and_Actions.md)
- Защита маршрутов на клиенте (ProtectedRoute компонент)
- Защита эндпоинтов на сервере (authenticate + authorize middleware)
- **ВАЖНО:** JWT секреты читать ТОЛЬКО из env, без fallback значений!

#### Валидация и обработка ошибок

- Валидация форм на клиенте ДО отправки (показывать ошибки под полями)
- Валидация данных на сервере с помощью Zod на КАЖДОМ эндпоинте
- Централизованный error handler middleware
- Человекочитаемые сообщения об ошибках на русском или английском
- HTTP-статусы соответствуют типу ошибки:
  - 200 — успешный GET/PUT
  - 201 — успешный POST (создание)
  - 204 — успешный DELETE
  - 400 — ошибка валидации
  - 401 — не авторизован
  - 403 — нет прав
  - 404 — не найдено
  - 500 — серверная ошибка

#### Нефункциональные требования

- **Доступность (a11y):** семантический HTML, alt для изображений, aria-labels для интерактивных элементов
- **CORS:** настроен для работы клиента с сервером (CLIENT_URL в env)
- **Helmet:** защита HTTP-заголовков
- **Rate Limiting:** на auth endpoints (5 попыток за 15 минут)
- **Логирование:** логи запросов и ошибок (можно использовать morgan или простой console.log с timestamps)
- **Пагинация:** для всех списков (page, pageSize, total, totalPages)

#### Контейнеризация (ОБЯЗАТЕЛЬНО!)

- **Dockerfile для сервера** — multi-stage build, использование `pnpm --filter`
- **Dockerfile для клиента** — для dev-сервера Vite
- **docker-compose.yml** — ВСЕ сервисы: postgres, server, web
- **healthcheck** для postgres с condition: service_healthy
- Файл `.env.example` с описанием ВСЕХ переменных окружения

#### Архитектура сервера (Clean Architecture)

```text
routes/ → controllers/ → services/ → prisma
```

- **Routes:** только определение маршрутов и подключение middleware
- **Controllers:** обработка HTTP (req/res), вызов сервисов, НЕ содержат бизнес-логику
- **Services:** ВСЯ бизнес-логика, работа с Prisma, не знают про HTTP
- **Middleware:** auth, validation, errorHandler, logger

## 5. ОБЯЗАТЕЛЬНЫЕ Best Practices (КРИТИЧЕСКИ ВАЖНО!)

### 5.1. Архитектура Backend (Clean Architecture)

```
routes/ → controllers/ → services/ → prisma
```

**ПРАВИЛА:**

- **Routes** — только определение маршрутов и middleware, никакой логики
- **Controllers** — только обработка HTTP (req/res), валидация входных данных, вызов сервисов
- **Services** — ВСЯ бизнес-логика, не знают про HTTP
- **НИКОГДА** не пиши бизнес-логику в контроллерах!

```typescript
// ❌ НЕПРАВИЛЬНО — логика в контроллере
export async function createUser(req: Request, res: Response) {
  const user = await prisma.user.create({ data: req.body });
  res.json(user);
}

// ✅ ПРАВИЛЬНО — контроллер вызывает сервис
export async function createUser(req: Request, res: Response, next: NextFunction) {
  try {
    const result = await userService.create(req.body);
    res.status(201).json({ status: 'ok', data: result });
  } catch (error) {
    next(error);
  }
}
```

### 5.5. Валидация (Zod — ОБЯЗАТЕЛЬНО на ВСЕХ эндпоинтах!)

```typescript
// schemas/auth.schema.ts
import { z } from 'zod';

export const registerSchema = z.object({
  username: z.string()
    .min(3, 'Username must be at least 3 characters')
    .max(30, 'Username must be at most 30 characters')
    .regex(/^[a-zA-Z0-9_]+$/, 'Only letters, numbers and underscores'),
  password: z.string()
    .min(8, 'Password must be at least 8 characters'),
});

export const loginSchema = z.object({
  username: z.string().min(1, 'Username is required'),
  password: z.string().min(1, 'Password is required'),
});

// middleware/validate.ts
import { ZodSchema } from 'zod';
import { Request, Response, NextFunction } from 'express';

export function validate(schema: ZodSchema) {
  return (req: Request, res: Response, next: NextFunction) => {
    const result = schema.safeParse(req.body);
    if (!result.success) {
      return res.status(400).json({
        status: 'error',
        error: {
          code: 'validation_error',
          message: 'Invalid input data',
          details: result.error.flatten().fieldErrors,
        },
      });
    }
    req.body = result.data;
    next();
  };
}
```

### 5.6. Обработка ошибок (централизованная!)

```typescript
// lib/errors.ts
export class AppError extends Error {
  constructor(
    public statusCode: number,
    public code: string,
    message: string,
    public details?: Record<string, unknown>
  ) {
    super(message);
  }
}

export class NotFoundError extends AppError {
  constructor(resource: string) {
    super(404, 'not_found', `${resource} not found`);
  }
}

export class UnauthorizedError extends AppError {
  constructor(message = 'Authentication required') {
    super(401, 'unauthorized', message);
  }
}

export class ForbiddenError extends AppError {
  constructor(message = 'Access denied') {
    super(403, 'forbidden', message);
  }
}

// middleware/errorHandler.ts
import { ErrorRequestHandler } from 'express';
import { AppError } from '../lib/errors';
import logger from '../lib/logger';

export const errorHandler: ErrorRequestHandler = (err, req, res, _next) => {
  logger.error({ err, path: req.path, method: req.method }, 'Request error');

  if (err instanceof AppError) {
    return res.status(err.statusCode).json({
      status: 'error',
      error: { code: err.code, message: err.message, details: err.details },
    });
  }

  return res.status(500).json({
    status: 'error',
    error: { code: 'internal_server_error', message: 'An unexpected error occurred' },
  });
};
```

### 5.7. Frontend Best Practices

**API клиент с interceptors:**

```typescript
// api/client.ts
import axios, { InternalAxiosRequestConfig } from 'axios';

const API_URL = import.meta.env.VITE_API_URL;

export const api = axios.create({
  baseURL: API_URL,
  timeout: 10000,
});

api.interceptors.request.use((config: InternalAxiosRequestConfig) => {
  const token = localStorage.getItem('accessToken');
  if (token && config.headers) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

api.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      const refreshToken = localStorage.getItem('refreshToken');
      if (refreshToken && !error.config._retry) {
        error.config._retry = true;
        try {
          const { data } = await axios.post(`${API_URL}/auth/refresh`, { refreshToken });
          localStorage.setItem('accessToken', data.data.accessToken);
          error.config.headers.Authorization = `Bearer ${data.data.accessToken}`;
          return api(error.config);
        } catch {
          localStorage.clear();
          window.location.href = '/login';
        }
      }
    }
```
