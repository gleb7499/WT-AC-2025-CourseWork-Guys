# 2 Разработка алгоритмов

## 2.1 Описание сущностей и связей

Модель данных платформы «Учусь быстро» построена на основе реляционной парадигмы и включает восемь основных сущностей, связанных между собой отношениями один-ко-многим. Рассмотрим каждую сущность и её роль в системе.

**Пользователь (User)** является центральной сущностью системы. Каждый пользователь характеризуется уникальным идентификатором, именем пользователя, адресом электронной почты и хэшем пароля. Пользователь может иметь множество записей о прогрессе обучения и множество комментариев, но каждая запись прогресса и каждый комментарий принадлежат только одному пользователю.

**Курс (Course)** представляет собой образовательную программу, состоящую из набора уроков. Курс имеет идентификатор, название и текстовое описание. Один курс может содержать множество уроков и тестов, при этом каждый урок и тест принадлежат только одному курсу.

**Урок (Lesson)** является единицей образовательного контента внутри курса. Урок включает идентификатор, ссылку на родительский курс, название, URL видеоматериала и текстовое содержание. С уроком связаны записи о прогрессе пользователей и комментарии.

**Прогресс (Progress)** фиксирует факт завершения пользователем конкретного урока. Запись прогресса содержит идентификатор, ссылки на пользователя и урок, а также булев флаг завершения. Между пользователем и уроком может существовать не более одной записи прогресса.

**Комментарий (Comment)** представляет собой текстовое сообщение пользователя, относящееся к конкретному уроку. Комментарий включает идентификатор, ссылки на пользователя и урок, и текстовое содержание. Один пользователь может оставлять множество комментариев, один урок может иметь множество комментариев.

**Тест (Test)** представляет собой набор вопросов для проверки знаний по определенному курсу. Тест характеризуется идентификатором, ссылкой на курс, названием и описанием. Один тест состоит из множества вопросов.

**Вопрос (Question)** является элементом теста и содержит формулировку задания. Вопрос имеет идентификатор, ссылку на родительский тест и текст вопроса. С каждым вопросом связано множество вариантов ответа.

**Вариант ответа (Option)** представляет собой один из возможных ответов на вопрос. Вариант ответа включает идентификатор, ссылку на вопрос, текст ответа и булев флаг правильности. Для каждого вопроса может быть определен один или несколько правильных вариантов.

**Попытка прохождения теста (Attempt)** фиксирует результаты прохождения теста пользователем. Попытка содержит идентификатор, ссылки на пользователя и тест, количество правильных ответов и общее количество вопросов. С попыткой связан набор конкретных ответов пользователя.

**Ответ на вопрос (AttemptAnswer)** связывает попытку прохождения теста с конкретным выбранным вариантом ответа на вопрос. Включает идентификатор, ссылки на попытку, вопрос и выбранный вариант ответа.

Связи между сущностями обеспечивают целостность данных и позволяют эффективно выполнять запросы для получения связанной информации, например, всех уроков курса или всех комментариев к определенному уроку.

## 2.2 Алгоритм формирования списка курсов

Формирование списка курсов для отображения на главной странице реализуется следующим алгоритмом:

1. Получить все записи курсов из базы данных без фильтрации.
2. Для каждого курса извлечь идентификатор, название и описание.
3. Если пользователь авторизован, определить его идентификатор из сессии.
4. Сформировать HTML-представление списка курсов с передачей данных в шаблон.
5. Вернуть сформированную страницу клиенту.

Данный алгоритм обеспечивает универсальность отображения: все пользователи видят один и тот же список курсов, независимо от статуса аутентификации, что соответствует концепции открытого доступа к образовательному контенту в рамках MVP.

## 2.3 Алгоритм отслеживания прогресса

Алгоритм отметки урока как завершенного включает следующие шаги:

1. Проверить наличие активной пользовательской сессии. Если сессия отсутствует, перенаправить пользователя на страницу аутентификации.
2. Извлечь идентификатор пользователя из сессии.
3. Получить идентификатор урока из параметров запроса.
4. Выполнить поиск существующей записи прогресса для данной пары пользователь-урок.
5. Если запись прогресса существует, установить флаг завершения в значение «истина».
6. Если запись прогресса не существует, создать новую запись с флагом завершения «истина».
7. Сохранить изменения в базе данных.
8. Вернуть подтверждение клиенту (перенаправление на страницу урока или JSON-ответ).

Алгоритм поддерживает идемпотентность: повторная отметка одного и того же урока не приводит к созданию дублирующих записей. Использование транзакций базы данных обеспечивает атомарность операции.

## 2.4 Алгоритм прохождения теста

Алгоритм прохождения теста состоит из двух этапов: отображение теста и обработка ответов.

**Отображение теста:**

1. Получить идентификатор теста из параметров запроса.
2. Извлечь из базы данных информацию о тесте, включая все связанные вопросы.
3. Для каждого вопроса извлечь все варианты ответов.
4. Сформировать HTML-форму с вопросами и вариантами ответов в виде радиокнопок или флажков.
5. Вернуть сформированную страницу клиенту.

**Обработка ответов:**

1. Получить идентификатор теста и идентификатор пользователя (если авторизован).
2. Извлечь из параметров запроса выбранные пользователем варианты ответов для каждого вопроса.
3. Для каждого вопроса теста определить правильный вариант ответа.
4. Сравнить выбранные пользователем варианты с правильными ответами.
5. Подсчитать количество правильных ответов.
6. Создать запись попытки прохождения теста с указанием количества правильных ответов и общего количества вопросов.
7. Сохранить запись попытки в базе данных.
8. Отобразить результаты теста пользователю.

Алгоритм обеспечивает объективную автоматизированную проверку знаний без возможности изменения результатов после отправки ответов.

## 2.5 Алгоритм аутентификации пользователя

Аутентификация пользователей в системе выполняется по следующему алгоритму:

1. Получить из формы имя пользователя (или адрес электронной почты) и пароль.
2. Выполнить поиск пользователя в базе данных по имени пользователя или адресу электронной почты.
3. Если пользователь не найден, вернуть сообщение об ошибке «Неверные учетные данные».
4. Если пользователь найден, извлечь хэш пароля из базы данных.
5. Вычислить хэш введенного пароля с использованием той же функции хэширования и соли, что использовались при регистрации [2].
6. Сравнить вычисленный хэш с хэшем из базы данных.
7. Если хэши совпадают, создать серверную сессию и сохранить в ней идентификатор пользователя.
8. Если хэши не совпадают, вернуть сообщение об ошибке «Неверные учетные данные».
9. При успешной аутентификации перенаправить пользователя на главную страницу.

Использование криптографически стойких функций хэширования обеспечивает защиту паролей от компрометации даже в случае утечки базы данных. Серверные сессии Flask управляются с помощью защищенных cookie-файлов, подписанных секретным ключом приложения.

## 2.6 Транзакции и согласованность данных

Система использует встроенные механизмы транзакций SQLAlchemy для обеспечения согласованности данных [3]. Каждая операция изменения данных (создание, обновление, удаление) выполняется в контексте транзакции, которая автоматически откатывается при возникновении ошибок.

Типичный паттерн работы с транзакциями в системе включает следующие шаги:

1. Начать неявную транзакцию при первом обращении к базе данных в рамках запроса.
2. Выполнить все необходимые операции с объектами модели (создание, изменение атрибутов).
3. Вызвать метод commit для сохранения изменений в базе данных.
4. При возникновении исключения SQLAlchemy автоматически откатывает транзакцию.

Внешние ключи в базе данных SQLite настроены с опцией каскадного удаления для определенных связей, что обеспечивает автоматическое удаление зависимых записей при удалении родительских объектов. Например, при удалении курса автоматически удаляются все связанные уроки и тесты.

Индексы создаются автоматически для первичных ключей и столбцов с ограничением уникальности (имя пользователя, адрес электронной почты), что обеспечивает быстрый поиск и предотвращает дублирование данных.
