# 1 Постановка задачи

## 1.1 Исходные данные

Исходными данными для разработки платформы «Учусь быстро» являются требования к системе управления образовательным контентом с поддержкой видеоуроков и автоматизированного тестирования. Система должна обеспечивать хранение и представление следующих типов данных:

- информация о курсах: идентификатор, название, описание;
- информация об уроках: идентификатор, принадлежность к курсу, название, URL видео, текстовый контент;
- данные пользователей: идентификатор, имя пользователя, адрес электронной почты, хэш пароля;
- записи о прогрессе обучения: связь пользователя и урока, статус завершения;
- тесты и вопросы: идентификатор теста, принадлежность к курсу, название, описание, набор вопросов с вариантами ответов;
- попытки прохождения тестов: связь с пользователем и тестом, результаты (количество правильных ответов из общего числа);
- комментарии к урокам: связь с пользователем и уроком, текст комментария.

Данные должны храниться в реляционной базе данных с соблюдением целостности связей между сущностями. Форматы представления данных на клиенте — HTML-страницы для пользовательского интерфейса и JSON для API-взаимодействия.

## 1.2 Функциональные требования

Функциональные требования определяют основные возможности системы, необходимые для реализации MVP:

**Управление пользователями**

Система должна обеспечивать регистрацию новых пользователей с указанием имени пользователя, адреса электронной почты и пароля. Пароли должны храниться в виде хэшей с использованием криптографически стойких алгоритмов [2]. Система должна поддерживать аутентификацию пользователей по имени пользователя или адресу электронной почты с проверкой введенного пароля. После успешной аутентификации создается пользовательская сессия на основе механизма серверных сессий Flask.

**Управление курсами и уроками**

Система должна предоставлять возможность просмотра списка доступных курсов на главной странице. Каждый курс может содержать произвольное количество уроков. При просмотре детальной информации о курсе отображается список его уроков с указанием статуса завершения для авторизованного пользователя. Уроки должны содержать текстовое описание и ссылку на видеоматериал.

**Отслеживание прогресса**

Авторизованные пользователи должны иметь возможность отмечать уроки как завершенные. Информация о завершенных уроках сохраняется в базе данных и отображается при повторном просмотре курса. Система должна поддерживать как синхронную отметку прогресса через форму, так и асинхронную через AJAX-запросы.

**Система тестирования**

Для каждого курса может быть создано одно или несколько тестов. Тест состоит из набора вопросов, каждый из которых имеет несколько вариантов ответа, один или несколько из которых являются правильными. Пользователи должны иметь возможность проходить тесты, выбирая ответы на вопросы. После завершения теста система автоматически проверяет ответы, подсчитывает количество правильных ответов и отображает результат. Попытки прохождения тестов сохраняются в базе данных для последующего анализа.

**Комментарии к урокам**

Авторизованные пользователи должны иметь возможность оставлять текстовые комментарии к урокам. Комментарии отображаются на странице урока в порядке добавления.

## 1.3 Нефункциональные требования

**Производительность**

Система должна обеспечивать приемлемое время отклика при обработке пользовательских запросов. Для типичных операций просмотра списков и детальной информации время отклика не должно превышать 2 секунд при условии стабильного подключения к сети. Запросы к базе данных должны выполняться эффективно с использованием индексов по первичным и внешним ключам.

**Безопасность**

Пароли пользователей должны храниться исключительно в виде хэшей с использованием алгоритмов семейства PBKDF2 или bcrypt [2]. Система должна предотвращать несанкционированный доступ к функциям, требующим аутентификации. Сессии пользователей должны иметь ограниченное время жизни и безопасно управляться на серверной стороне. Все пользовательские вводы должны валидироваться для предотвращения типичных уязвимостей веб-приложений.

**Масштабируемость**

Архитектура системы должна позволять добавление новых курсов, уроков и тестов без изменения кодовой базы. Структура базы данных должна поддерживать расширение новыми сущностями при необходимости.

**Надежность**

Система должна корректно обрабатывать ошибки и предоставлять информативные сообщения пользователю при возникновении исключительных ситуаций. Целостность данных должна поддерживаться средствами реляционной базы данных через механизм внешних ключей и транзакций.

## 1.4 Ограничения и допущения

При разработке системы приняты следующие ограничения и допущения:

Видеоконтент не хранится непосредственно в системе — используются только ссылки на внешние источники видеохостинга. Это снижает требования к дисковому пространству и пропускной способности канала, но требует доступности внешних сервисов.

Система не предусматривает разграничение ролей пользователей на административные и обычные в рамках MVP. Все зарегистрированные пользователи имеют одинаковые права доступа к функциям просмотра курсов, отметки прогресса, прохождения тестов и комментирования.

Административные функции создания и редактирования курсов, уроков и тестов не реализованы в пользовательском интерфейсе MVP. Начальное наполнение базы данных осуществляется через скрипт инициализации.

Система не включает механизмы платежей и монетизации контента, ограничиваясь свободным доступом ко всем материалам для зарегистрированных пользователей.

Отсутствует полнофункциональная система уведомлений и коммуникации между пользователями. Комментарии являются односторонними сообщениями без возможности ответов и древовидной структуры обсуждений.

Система рассчитана на работу в однопользовательском режиме или с небольшим числом одновременных пользователей. Для работы в условиях высокой нагрузки потребуется дополнительная оптимизация и масштабирование инфраструктуры.

## 1.5 Чеклист приёмки MVP

Критерии приёмки MVP определены в виде технического чеклиста, проверяемого автоматизированными тестами:

- регистрация нового пользователя с корректными данными завершается успешно, пользователь сохраняется в базе данных;
- попытка регистрации с уже существующим именем пользователя или адресом электронной почты отклоняется с соответствующим сообщением;
- аутентификация с корректными учетными данными завершается успешно, создается пользовательская сессия;
- аутентификация с некорректными учетными данными отклоняется;
- главная страница отображает список доступных курсов;
- страница курса отображает список уроков с корректной информацией;
- авторизованный пользователь может отметить урок как завершенный;
- информация о завершенных уроках корректно отображается при повторном просмотре;
- авторизованный пользователь может оставить комментарий к уроку;
- комментарии отображаются на странице урока;
- тест отображается со всеми вопросами и вариантами ответов;
- система корректно проверяет ответы и подсчитывает результаты теста;
- попытка прохождения теста сохраняется в базе данных с корректными данными.

Все указанные критерии проверяются набором модульных и интеграционных тестов с использованием фреймворка pytest.
