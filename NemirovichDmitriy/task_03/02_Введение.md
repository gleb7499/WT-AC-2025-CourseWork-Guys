# Введение

Планирование поездок — задача, требующая координации множества аспектов: маршрута, бюджета, расписания и совместной работы участников. В современном мире, где путешествия становятся всё более доступными и популярными, особенно актуальна потребность в инструментах, позволяющих эффективно организовывать поездки в группах. Существующие решения либо слишком сложны для повседневного использования, либо не обеспечивают возможностей для полноценной совместной работы нескольких участников над одним маршрутом. Это приводит к необходимости использовать разрозненные инструменты для разных задач: одно приложение для маршрута, другое для бюджета, третье для заметок. Отсутствие единой платформы снижает эффективность планирования и увеличивает вероятность ошибок.

Разработка специализированной платформы для планирования поездок с акцентом на совместную работу и управление бюджетом позволит решить указанные проблемы. Пользователям необходим инструмент, объединяющий функции построения маршрута, управления расходами, ведения совместных заметок и координации участников в единой системе [2].

**Цель работы**: разработать веб-платформу «Поехали!» для планирования совместных поездок с функциями управления маршрутами, бюджетом и участниками.

**Задачи работы**:

1. Провести анализ предметной области и сформулировать функциональные и нефункциональные требования к системе.
2. Спроектировать модель данных и определить связи между основными сущностями системы.
3. Разработать алгоритмы обработки данных для ключевых операций: создания и изменения поездок, управления остановками, учёта расходов и совместной работы.
4. Реализовать серверную часть приложения с REST API и механизмом аутентификации на основе JWT.
5. Разработать клиентское веб-приложение с интерфейсом для работы с поездками, маршрутами, бюджетом и участниками.
6. Провести тестирование функциональности и подготовить инструкции по развёртыванию системы.

**Описание варианта**: согласно варианту 35, тема проекта — «Платформа планирования поездок с маршрутами, бюджетом и совместной работой». Основные требования включают реализацию работы с поездками, остановками маршрута, заметками и расходами. API должен предоставлять endpoints для операций с ресурсами /trips, /stops, /notes, /expenses. Ключевые сущности данных: Trip (поездка), Stop (остановка), Note (заметка), Expense (расход), User (пользователь). Критерий приёмки MVP: корректное создание поездки и возможность совместной работы (шаринг) между пользователями.

Работа структурирована следующим образом. В первом разделе представлена постановка задачи с описанием исходных данных, функциональных и нефункциональных требований. Во втором разделе описана разработка алгоритмов для ключевых операций системы. В третьем разделе представлена архитектура программного решения, технологический стек, модель данных и спецификация API. В заключении подведены итоги разработки и намечены направления дальнейшего развития системы.
