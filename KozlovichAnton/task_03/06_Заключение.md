# Заключение

В ходе выполнения курсовой работы была разработана полнофункциональная система управления багами «Не баг, а фича?», представляющая собой веб-приложение с архитектурой клиент-сервер для отслеживания и управления дефектами в программных проектах. Система реализует комплексный подход к организации процессов обработки багов с поддержкой множества проектов, гибкой системой управления правами доступа и визуализацией данных.

Были решены все поставленные задачи. Проведён анализ требований к функциональности системы, определён состав основных сущностей предметной области: пользователи, проекты, баги, участники проектов, комментарии и вложения. Спроектирована реляционная модель данных, обеспечивающая эффективное хранение и извлечение информации с использованием индексов по часто запрашиваемым полям. Разработаны алгоритмы ключевых операций системы, включая аутентификацию пользователей с механизмом ротации JWT токенов, проверку прав доступа на основе глобальных и проектных ролей, формирование списков багов с применением фильтрации и пагинации, обработку файловых вложений с валидацией и безопасным хранением.

Реализована серверная часть на платформе Node.js с использованием фреймворка Express, обеспечивающая REST API для выполнения всех необходимых операций. Применение Prisma ORM обеспечило типобезопасность запросов к базе данных и автоматизацию работы с миграциями. Валидация входных данных осуществляется с использованием библиотеки Zod, что предотвращает обработку некорректных данных. Централизованный обработчик ошибок обеспечивает единообразие ответов API и предотвращает утечку деталей реализации.

Разработана клиентская часть в виде одностраничного приложения на библиотеке React, предоставляющая интуитивно понятный пользовательский интерфейс для работы со всеми функциями системы. Использование react-router обеспечивает навигацию без перезагрузки страницы. Реализован механизм автоматического обновления токенов доступа при их истечении, обеспечивающий непрерывность работы пользователя без необходимости повторной аутентификации.

Обеспечена безопасность приложения путём внедрения множества защитных механизмов. Пароли хешируются с использованием алгоритма bcrypt. Токены обновления хранятся в защищённых HTTP-only cookie, недоступных для JavaScript кода. Реализован механизм обнаружения повторного использования токенов, сигнализирующий о возможной компрометации. Текстовый ввод пользователей проходит санитизацию для защиты от XSS-атак. Применяются заголовки безопасности через библиотеку helmet. Ограничение скорости запросов предотвращает атаки типа брутфорс и DoS.

Функциональность системы полностью соответствует требованиям варианта и критериям приёмки MVP. Реализовано управление проектами с настройкой публичности и назначением владельца. Поддерживается добавление участников в проекты с назначением ролей: владелец, менеджер, разработчик, наблюдатель. Реализована регистрация багов с указанием приоритета и статуса, назначение багов на исполнителей, изменение статусов и приоритетов с учётом прав доступа. Поддерживается добавление текстовых комментариев к багам и прикрепление файлов с валидацией типа и размера. Реализована фильтрация багов по проекту, статусу, приоритету, исполнителю и автору с возможностью комбинирования условий. Реализована визуализация багов в виде Kanban-доски с колонками по статусам и применением фильтров.

Подготовлена документация, включающая описание архитектуры системы, спецификацию API с описанием всех endpoints и форматов данных, инструкции по настройке окружения и развёртыванию приложения, примеры использования для типичных сценариев работы.

Разработанная система может быть применена в практике команд разработки программного обеспечения для организации процессов отслеживания дефектов, управления задачами и координации работы между участниками проектов. Модульная архитектура и использование современных технологий обеспечивают возможность дальнейшего развития системы и добавления новой функциональности.

Направления дальнейшего развития системы могут включать реализацию истории изменений багов (audit log) для отслеживания всех модификаций, добавление real-time уведомлений о событиях с использованием WebSocket, интеграцию с внешними системами контроля версий (GitHub, GitLab) для автоматического связывания коммитов с багами, расширенную аналитику и отчётность по проектам (графики динамики решения багов, диаграммы распределения по исполнителям), поддержку пользовательских полей для багов, настраиваемых под специфику проекта, миграцию хранения файлов на объектное хранилище (S3-совместимое) для масштабируемости.

Таким образом, цель курсовой работы достигнута, все поставленные задачи выполнены. Разработанная система демонстрирует применение современных подходов и технологий веб-разработки для создания полнофункционального приложения управления багами с учётом требований безопасности, производительности и удобства использования.
