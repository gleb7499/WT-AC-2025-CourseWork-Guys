# Введение

В современной практике разработки программного обеспечения отслеживание дефектов и управление задачами являются критически важными процессами, напрямую влияющими на качество конечного продукта и эффективность работы команды разработчиков [1]. Системы управления багами (баг-трекеры) позволяют централизованно регистрировать обнаруженные проблемы, контролировать их жизненный цикл, назначать ответственных исполнителей и отслеживать прогресс выполнения работ. Применение специализированных инструментов для управления дефектами способствует повышению прозрачности процессов разработки, улучшению коммуникации между участниками проекта и сокращению времени на устранение ошибок.

Актуальность разработки систем управления багами обусловлена необходимостью обеспечения структурированного подхода к обработке дефектов в программных проектах различного масштаба. Существующие решения зачастую либо избыточно сложны для небольших команд, либо не предоставляют достаточной гибкости в настройке прав доступа и процессов работы с дефектами. Создание системы, сочетающей простоту использования с функциональной полнотой и гибкими механизмами управления доступом, представляет собой актуальную задачу в области разработки инструментов для поддержки процессов создания программного обеспечения.

Целью данной работы является разработка полнофункциональной системы управления багами «Не баг, а фича?» на основе современных веб-технологий с реализацией архитектуры клиент-сервер, системы аутентификации и авторизации пользователей, гибкого управления правами доступа и визуализации данных о дефектах.

Для достижения поставленной цели необходимо решить следующие задачи:

1. Провести анализ требований к функциональности системы и определить состав основных сущностей предметной области (пользователи, проекты, баги, комментарии, вложения).

2. Спроектировать модель данных с учётом требований к хранению информации о проектах, багах, участниках и их взаимосвязях, определить структуру базы данных и индексы для обеспечения производительности.

3. Разработать алгоритмы основных операций системы: аутентификации пользователей с использованием JWT токенов, проверки прав доступа на основе ролей, формирования списков и досок багов с применением фильтрации.

4. Реализовать серверную часть приложения на платформе Node.js с использованием фреймворка Express, обеспечив создание REST API для выполнения операций с данными, валидацию входных параметров и обработку ошибок.

5. Разработать клиентскую часть в виде одностраничного приложения на библиотеке React, реализовав пользовательский интерфейс для работы с проектами, багами, комментариями и вложениями.

6. Обеспечить безопасность приложения путём внедрения механизмов защиты от распространённых веб-уязвимостей, валидации пользовательского ввода и ограничения скорости запросов.

7. Подготовить документацию и инструкции по развёртыванию и эксплуатации системы.

Данная работа выполнена в соответствии с вариантом 11 «Баг-трекер «Не баг, а фича?»». Согласно спецификации варианта, система должна реализовывать следующий минимальный набор функций (MVP): управление проектами с указанием владельца и настройкой публичности, регистрацию багов с указанием приоритета и статуса, назначение багов на исполнителей, добавление комментариев и вложений, фильтрацию багов по различным критериям и визуализацию в виде Kanban-доски. Основные API-ресурсы включают endpoints для работы с проектами, багами, вложениями и пользователями. Модель данных включает сущности Bug, Project, User, ProjectMember, Attachment и Comment. Критериями приёмки MVP являются корректная работа фильтров и доски багов.
