# Реферат

Данная пояснительная записка описывает разработку полнофункциональной системы управления багами «Не баг, а фича?» — веб-приложения для отслеживания и управления дефектами в программных проектах. Система реализует модель багтрекера с поддержкой множества проектов, гибкой системой прав доступа через роли участников и полным жизненным циклом обработки багов.

Работа включает постановку задачи, проектирование моделей данных и алгоритмов, разработку программного обеспечения на базе современного технологического стека. Серверная часть реализована на Node.js с использованием фреймворка Express и ORM Prisma для взаимодействия с реляционной базой данных PostgreSQL. Клиентская часть представляет собой одностраничное приложение на React с TypeScript и react-router для навигации. Система обеспечивает аутентификацию пользователей на основе JWT токенов с механизмом ротации, авторизацию на основе ролей, валидацию данных, обработку ошибок и защиту от распространённых уязвимостей веб-приложений.

Функциональность системы охватывает создание и управление проектами, добавление участников с назначением ролей (владелец, менеджер, разработчик, наблюдатель), создание и редактирование багов с указанием приоритета и статуса, назначение багов на исполнителей, добавление комментариев и прикрепление файлов. Реализована визуализация багов в виде Kanban-доски с колонками по статусам и система фильтрации по различным критериям. Система поддерживает как публичные проекты, доступные всем пользователям, так и приватные проекты с ограниченным доступом через механизм участников проекта.

Разработанная система может применяться для организации процессов отслеживания дефектов в командах разработки программного обеспечения, технической поддержки пользователей и управления задачами в небольших и средних проектах.

**Ключевые слова:** баг-трекер, управление дефектами, веб-приложение, REST API, React, Node.js, Express, PostgreSQL, Prisma, JWT, аутентификация, авторизация, RBAC, TypeScript, SPA.
