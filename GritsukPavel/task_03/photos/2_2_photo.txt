Для рисунка 2.2 – Последовательность аутентификации пользователя:

Создать UML sequence diagram (диаграмму последовательности), показывающую процесс аутентификации пользователя. На диаграмме должны быть отображены:
- Три участника: Клиент (браузер), Сервер (API), База данных
- Последовательность взаимодействий при входе пользователя:
  1. Клиент отправляет POST /auth/login с email и password
  2. Сервер получает запрос, извлекает данные
  3. Сервер запрашивает пользователя из БД по email
  4. БД возвращает данные пользователя с passwordHash
  5. Сервер проверяет пароль (сравнение хешей)
  6. Сервер генерирует access и refresh токены
  7. Сервер сохраняет refresh-токен в БД
  8. Сервер отправляет клиенту: access-токен в JSON, refresh-токен в HTTP-only cookie
  9. Клиент сохраняет access-токен в памяти

Диаграмму можно создать с помощью инструментов PlantUML, Mermaid, draw.io или аналогичных.
